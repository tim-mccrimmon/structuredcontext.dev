## SCS v0.7.0 (Current)

**Theme:** context an AI assistant can maintain for you, under your approval.

0.7.0 implements [RFC 0002](https://github.com/tim-mccrimmon/structured-context-spec/blob/main/rfcs/RFC-0002-agent-mediated-scs.md),
agent-mediated SCS. An assistant can run the intake conversation, draft rules, review them,
and release and compile versions. Every change is confirmed by a person, and every version
can be verified afterwards.

:::note[Mostly additive]
SCDs and bundles written for 0.6 remain valid. The tools change more than the format:
context moves into its own Domain repository, and scripts that call the tools need
updating. See the [migration guide](/docs/specification/migration-0-7/).
:::

## What's new

- **[Agent Skills](/docs/skills/overview/).** Four skills, `scs-domain`, `scs-project`,
  `scs-validate`, and `scs-explain`, operate SCS through the tools. They install in Claude
  Code and Claude (claude.ai).
- **[Domain repositories](/docs/specification/domain-repositories/).** Context lives in
  its own git repository, `<name>-context/`, with the Domain under `domain/` and each Project
  under `projects/<name>/`. `scs new domain` creates it with a CI workflow and an `AGENTS.md`.
- **Versions you can verify.** A version is an annotated git tag. Its manifest records the
  named person who released it and a `content_digest`. Validation checks every tag against its
  digest, and `scs compile --version` compiles from the tag, not the working tree.
  `scs bundle release` versions a root bundle and the concept bundles it needs in one command.
- **[Section owners](/docs/specification/bundle-format/#section-owners).** Each concept
  bundle, and a Project bundle that lists SCDs directly, names the role accountable for it.
  The intake record names the person who holds each role, by name, with the email optional. A
  section can't be released until its role is held, and `scs bundle set-owner` sets the role.
- **Review packages (preview).** `scs view` renders a bundle as one self-contained HTML file
  for people who review it without git: every rule verbatim as the AI receives it, the section
  owners, the rules a Project inherits from its Domain, and the content digest checked against
  the release. The package format is expected to change in 0.8.
- **Released by, not approved by.** The person named at release authorizes the version into
  the repository. Formal approval, where context is certified, stays in the organization's own
  review or quality system, and its approval record should cite the version and its content
  digest, which the compiled artifact carries as `source_digest`. The field names
  (`--approved-by`) are unchanged.
- **A machine interface for agents.** Every command accepts `--json` and prints one result
  envelope. Commands that write accept `--dry-run`. Every diagnostic code is registered. New
  engine commands (`scs scd write`, `scs bundle pin`, `add-import`, `add-scd`, `remove-scd`,
  `scs add bundle --new`) let an agent maintain a workspace without editing files directly.
- **Intake and provenance.** `intake.yaml` records the intake answers, source documents,
  approvers, and review decisions. Items can carry `derived_from`, which validation checks and
  the compiler never emits.
- **Change summaries and stacks.** `scs bundle diff` reports what changed since the last
  version. `scs stack` previews several compiled artifacts loaded together, such as a personal,
  an organization, and a Project artifact.
- **Status and commits.** `scs status` reports where each workspace stands. `scs commit`
  commits one workspace with the author you name.
- **The `personal` ontology,** for one person's own context.
- **Reproducible builds.** When `SOURCE_DATE_EPOCH` is set, every timestamp the engine writes
  uses it, so a scripted build produces the same bytes.
- **[Examples](https://github.com/tim-mccrimmon/structured-context-spec/tree/main/examples)
  rebuilt as Domain repositories:** a fictional medical-device CDMO with one Project
  (`examples/medtech-cdmo/`) and a personal Domain (`examples/personal/`), each built through
  the engine, released, and compiled.
- **[Placement guidance](/docs/getting-started/placement/)** (provisional) for five AI
  services.

## Removed

- The `scs-vibe` and `scs-team` plugins. The Agent Skills replace them.
- `scs init`, `scs new --type`, and `scs bundle version --force` / `--no-git`.
- The examples `two-tier-governance`, `med-adherence`, and `chai-standards-bundle`. They remain
  at the `v0.6.0` tag.

## Known gaps

- The skills have been installed and tested in Claude Code and Claude. Cursor, Codex, and
  GitHub Copilot haven't been tried yet (planned for 0.8).
- The review package format and the placement guidance are provisional and expected to change
  in 0.8.
- An unresolved SCD in a bundle (`BUNDLE_SCD_UNRESOLVED`) stays a warning. A bundle that lists
  a missing SCD fails `--strict`, a release, and `scs compile`, while a draft still validates.
